Birds of Impalitism

I designed and implemented the save flow so player discoveries, collectibles, and progression could survive scene transitions and reloads. Birds of Impalitism is a vaporwave-inspired momentum shooter set in Palamus Mall.

What I Owned

I designed the progression data model and implemented the save controller, connecting player position, pickup IDs, completed dialogue reveals, and area tear counts. I also designed the dialogue interaction flow and coordinated the technical implementation with the team. The current code uses BatteryPickupManager and TimePeriodChanger for progression; the gallery records earlier battery and goggle setups.

Design problem

Players revisit areas to collect items, uncover dialogue, and unlock progression. Returning to a scene should preserve those discoveries rather than make the player repeat them. The save flow needed to reconstruct that experience, not just restore a position.

Constraints

Scene objects are recreated on transitions, while progression managers carry state between scenes. I needed explicit ownership for pickup IDs, dialogue reveal IDs, and area counts, and a clear handoff between in-memory state and a saved snapshot.

Featured work

Three selected parts of my work on Birds of Impalitism.

01 / Featured work

Deciding what the save file owns

Because revisiting a space should preserve the player’s progress, the save needed to remember both where they were and what they had completed. I used one SaveData snapshot for position and yaw, collected pickup IDs, completed dialogue reveal IDs, three area tear counts, and the last entered area.

SaveGameController gathers a snapshot and SaveSystem writes it to save.json. BatteryPickupManager exports its pickup and reveal ID sets as lists, while registered TimePeriodChanger components copy the three shared area counts. The area counts belong to Entrance, Beach, and FoodCourt rather than individual scene save files.

02 / Featured work

Keeping progression through scene changes

A collected pickup or completed dialogue reveal needs to stay completed when the player leaves an area. The controller and managers persist between scenes, while newly created scene objects read their completion IDs from BatteryPickupManager.

InteractableLevelTear saves before level entry and records the return scene in memory. The win flow and level pause menu queue a load before returning. On the next sceneLoaded event, the controller restores the snapshot and refreshes the area UI. Other scene changes carry manager state in memory without automatically reading the file.

03 / Featured work

Rebuilding the world on load

A successful load should make the scene match the player’s discoveries: collected items stay collected and revealed objects remain visible. BatteryPickupManager rebuilds its ID sets and resets pickups and dialogue reveals, including inactive objects. Collected ordinary pickups stay hidden, their connected objects become visible, and completed reveals restore their object visibility.

LoadGame also restores player position and yaw with CharacterController temporarily disabled, then reloads the area counts and updates the last area's UI. The code checks for a missing file or player; the design document records the remaining limits, including dictionary serialization and malformed-save handling.

Project takeaway

Birds of Impalitism made state ownership a concrete design concern for me. Carrying manager state between scenes, writing a snapshot to disk, and restoring scene objects each need an explicit handoff. Reviewing the save fields against their runtime owners also shows where older features and unused fields have stopped matching the implementation.
